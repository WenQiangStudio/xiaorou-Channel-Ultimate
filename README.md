## 妈妈级人设：怎么做到「不过火」

核心是一句话：**温度体现在「做事」上，不是体现在「嘴上」**。主动把方案给全、把坑提前说、出错先兜住，但关怀只捎带一句就回到问题。

- 熬夜/通宵：给完解决方案，补一句「弄完早点休息」，不再展开。
- 出错/卡壳：先给解决办法，再温和提醒一句「下次注意核对前提」。
- 生病/焦虑：先接住一句「先顾好自己」，再处理问题。
- 专业问题：全程保持专业，不强行插入关怀，不把技术聊成家常。
- 不做的事：不叫「宝贝/乖」，不堆语气词，不替用户做决定，不说教。

具体规则全文在 `persona/system_prompt.md`，训练前先读它。

## 工具能力（至尊版核心新增）

原版只有纯对话，至尊版内置了可扩展的工具调用框架。搜索、抓取、计算三个核心工具纯标准库实现、零额外依赖；语音识别/合成（asr/tts）是**可编程调用的底层工具**，需要可选依赖（faster-whisper / ChatTTS），装好后用 `reg.call("asr"/"tts")` 接入你的语音前端——本工程本身不内置「麦克风自动听 → 扬声器自动说」的闭环，那个由手机 App / WebUI 层负责调用这两个工具实现：

| 工具 | 能力 | 何时用 |
|---|---|---|
| `search` | 联网搜索，返回标题+链接+摘要 | 实时新闻、行情、最新政策、最新库用法 |
| `web_fetch` | 抓取网页正文 | 读取指定 URL 内容 |
| `calculator` | 安全计算（AST 求值，杜绝 eval 注入） | 数值计算，不硬算不瞎编 |
| `asr` | 语音转文字（faster-whisper，本地离线） | 语音输入、录音转文字 |
| `tts` | 文字转语音（ChatTTS，中文自然） | 语音回答、朗读 |

### 工具增强层（自动触发，无需手动调用）

`tools/agent.py` 把**搜索、计算、网页抓取**三个工具真正接进了对话循环：根据你这句话，自动判断该不该调工具，命中就调、把结果拼进上下文，模型据此回答。已接入命令行 `infer.py` 和生产多用户 `api_server.py`，两种模式都生效。语音的 asr/tts 不在此列（需手动 `reg.call`）。规则集中、一眼能改：

| 触发信号 | 自动调用 | 例子 |
|---|---|---|
| 纯算式 | `calculator` | 「2^10」→ 直接算出 1024 |
| 时效词（最新/行情/价格/今天/天气…） | `search` | 「5090 显卡什么行情」→ 联网查 |
| 消息里带 URL | `web_fetch` | 「总结这个网页」→ 抓正文 |

诚实说明：这是「规则触发」，不是 function calling。真正的 function calling 需要专门微调模型输出工具调用指令；规则触发是离线环境下务实、可控、可解释的折中，触发规则集中在 `tools/agent.py` 的 `TOOL_RULES`，一句话就能改。

```python
from tools import get_registry
reg = get_registry()
reg.call("calculator", {"expr": "1.05^20"})   # {'ok': True, 'result': 2.653...}
reg.call("search", {"query": "5090 显卡 行情"})
reg.call("web_fetch", {"url": "https://..."})
reg.call("asr", {"audio_path": "/path/voice.wav"})     # 语音转文字
reg.call("tts", {"text": "你好，我是小柔"})            # 文字转语音
```

新增工具只需写一个 `func(params: dict) -> dict` 函数，`reg.register(func)` 即可挂载。

## 底座选型（服务器级 MoE 为主，单卡备选）

| 场景 | 底座 | 参数量 | 显存/内存 | 用途 |
|---|---|---|---|---|
| 服务器级主力 | DeepSeek V4.1 Flash | 552B MoE / 8B 激活 | 8×80G（FP8） | 最强中文，MIT，官方多卡部署 |
| 服务器级全模态 | MiMo V2.6 Flash | 309B MoE / 15B 激活 | 4 卡（TP=EP=4） | 图片/视频/音频全模态，MIT |
| 顶配（可选） | MiMo V2.6 Pro | 1.02T / 42B 激活 | 8 卡 500GB+ | 旗舰级，1M 上下文 |
| 单卡备选 | Qwen3.8-27B | 27B 稠密 | 24G（Q4） | 没有多卡时的退路 |

**为什么是 MoE 不是堆稠密参数**：2026 年的服务器级最强都是 MoE 架构——用极少的激活参数（8B/15B）换来旗舰级能力，比堆 72B/405B 稠密模型又快又强。DeepSeek V4.1 Flash 是当前中文场景的服务器级最优解。

**确切 repo 名以部署时在 Hugging Face 搜索为准**，这些是官方/社区确认存在的模型系列；改 `config.json` 里的 `base_model` 即可切换，MoE 模型部署走 vLLM/SGLang 多卡推理。

## 训练流程（沿用原版 SFT + DPO 两阶段）

1. **SFT 监督微调**（QLoRA，4bit）：学习妈妈级人设、场景表达、工具调用格式。
2. **DPO 偏好对齐**：校准「太冷漠/太唠叨」「专业不足/废话太多」「瞎编/坦白」的偏差。

数据体系持续扩充，当前 `data/seed_sft.jsonl` 是妈妈级人设的种子样本，按场景继续加即可。
